# 项目介绍

「抖音续火花控制台」是一个跑在**自己机器上**的抖音续火花自动化：定时用无头浏览器打开抖音网页版聊天页，给指定好友发送消息来续火花，并把「今天发没发、发给了谁、有没有发错人」如实记录下来，在一个网页控制台里能看到全部细节。

## 它由哪几部分组成

| 部分 | 作用 |
| --- | --- |
| **派发器**（systemd timer + `core/schedule.py`） | 每 5 分钟敲一次门：谁到点、谁今天已经发过、谁要再试。定时器本身不判断「今天发没发」 |
| **发送链路**（`core/tasks.py` → `core/douyin_im.py`） | 逐账号、逐目标：选会话 → 输入消息 → 点发送 → 收回执 → 核验收件人 |
| **网页控制台**（`webui/`） | 账号卡、运行明细、日志尾部、手动运行、空跑触发、配置编辑、磁盘维护、扫码登录 |
| **配置工具**（`configTool/`） | tkinter 图形界面：生成/修改 `.env`、抓取登录态 |
| **运维脚本**（`deploy/`、`main.py prune`） | 幂等安装、systemd 单元、logrotate、磁盘与资料目录维护 |

## 特性

- **多账号、多目标**：一个账号可以给多个好友续火花，每个账号有自己的消息文本与发送时间。
- **发送回执核验**：只有「HTTP 回执 ok」且「发送后当前会话就是目标会话」才算强确认；拿不到收件人身份时如实降级成弱证据，不会把「不确定」写成「成功」。
- **可信输入**：聊天页编辑器是 EditorKit（Slate 系）。输入走「全选 + CDP 插入文本覆盖」，发送前逐行比对读回内容；落地不精确就重试或退回覆盖式重打，两条都不成**拒绝发送**。
- **掉登录不再静默丢一天**：运行期发现登录失效记成 `error`，重新扫码后当天自动补发。
- **空跑（dry-run）**：`select` 只跑到选中会话，`full` 走完输入与校验但不点发送。
- **限流熔断**：命中「操作频繁 / 安全验证」一类文案即中止本轮并进入冷却。
- **磁盘维护**：登录资料目录等价于凭据、浏览器缓存会持续增长；面板可手动清理，定时器每周自动清一次，三条安全线保证「绝不误删在册账号」。
- **隐身浏览器**：内置 cloakbrowser 隐身 Chromium，可固定指纹；支持配套代理对齐出口 IP。

## 运行原理

用 cloakbrowser（底层 Playwright）驱动无头 Chromium，登录抖音网页聊天版（<https://www.douyin.com/chat>），在配置的时间点给目标好友发送续火消息；每轮的结构化结果写进 `logs/runs.jsonl`，网页控制台读的就是它。

## 部署方式概览

| 方式 | 适用场景 | 说明 |
| --- | --- | --- |
| **源码部署 + systemd** | 有常开的服务器 / 小主机 | **本项目推荐**：web 常驻 + timer 每 5 分钟敲门，见 [源码部署](../deploy.md) |
| Docker | 有服务器 / NAS | 容器内由 cron 每 5 分钟敲门，见 [Docker 部署](../deploy/docker.md) |
| GitHub Action | 无服务器 | 上游形态，出口 IP 漂移、登录态容易掉，本仓库不使用 |

具体怎么选，见 [选择部署方式](../guide/01-选择部署方式.md)。
