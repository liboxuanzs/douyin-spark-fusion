# 抖音续火花控制台

给固定的几个朋友按时发一句「续火花」，发没发出去它自己核对。

你在网页上配好账号、好友、内容、时间，剩下的交给它：每天到点开一次真实浏览器，把话发出去，再把结果写进账本。

## 这是给谁用的

- 每天要给固定的三五个人续火花，手动发嫌烦，断签又心疼；
- 手上有一台常年开着的 Linux 机器（小主机、NAS、云服务器都行）；
- 愿意花十分钟装一次，之后每天瞄一眼面板。

它做的事很简单：**到点，用真浏览器，把你想说的话发给指定的人，然后核对到底发没发成。**

它不适合：批量养号、刷量、给几十上百个陌生人发消息。

## 它比"自己点一下"强在哪

| 手动发 | 用它 |
| --- | --- |
| 每天记着点开抖音、翻会话 | 到点自动发，当天出错还会继续试 |
| 发完不确定对方收到没有 | 拿抖音的回执核对，发没发有账可查 |
| 多个号来回切 | 每个号各自的时间、内容、好友名单、出口 |
| 换设备就掉登录 | 登录态和浏览器快照存下来，扫一次能用很久 |
| 半夜/出差容易断 | 掉登录会提示，重新扫完当天补发 |

最要紧的一条：**它不会"点了发送就记成功"。** 只看到按钮变灰就写"今天已发"是这类工具最常见的自欺；这里的标准是——抖音的回执说发出了，**并且**当前会话确实是那个好友，才算发过。掉登录、被顶号、一条都没发出去，都会记成失败。

## 它做不到什么

- 一条内容发给这个账号的**全部**好友，每个好友只有 `[API]`（每日一言）那句不同。想每人一句不同的话得改数据模型。
- 不做并发、不做多机：同一个账号同一时间只允许一个浏览器。
- 不绕风控：命中验证/限流就停下来冷却，而不是换 IP 继续打。
- 需要一台**24 小时开机、出口 IP 稳定**的机器。出口 IP 一变登录就会掉——这是掉登录的头号原因。

## 开始之前，准备三样东西

1. **一台 Linux 机器**：Ubuntu 22.04 / 24.04，有 root 或 sudo，能长期开机，磁盘留 5 GB 以上。
2. **能正常上网的网络**：这台机器能打开抖音网页；出口 IP 稳定（家庭宽带、固定 IP 的云服务器都行，别用会跳节点的代理或机场）。
3. **手机上的抖音 App**：第一次登录要扫码；有风控的号可能还要收一条短信验证码，需要你本人在场。

## 十分钟上手

### 第 1 步：装（3~5 分钟）

```bash
git clone https://github.com/liboxuanzs/douyin-spark-fusion.git
cd douyin-spark-fusion
sudo bash deploy/install.sh --dry-run   # 先看它准备做什么，不动系统
sudo bash deploy/install.sh             # 真装
```

它会：把代码放到 `/opt/douyin-spark-fusion`、建 Python 环境、装依赖、下载一个 Chromium（几百 MB）、从 `.env.example` 生成 `.env`、装好 systemd 单元（面板 / 每日派发 / 每日体检）。

它**不会**替你开定时发送——最后一步等你自己确认。

想换目录：`APP_DIR=/你的路径 sudo bash deploy/install.sh`。重复执行可以用来升级，不会覆盖已有的 `.env`。

### 第 2 步：设一个面板口令

面板默认对外监听 `0.0.0.0:8787`，没有口令会**故意拒绝启动**（免得局域网里谁都能进）。所以先设一个：

```bash
cd /opt/douyin-spark-fusion
.venv/bin/python -m webui.reset_password
```

按提示输两遍（不回显）。它会把口令写进 `.env`、顺手重启面板、等到 `/healthz` 通了才返回。以后忘了口令也用它，不用先登进面板。

### 第 3 步：打开面板

```bash
sudo systemctl enable --now douyin-spark-fusion-web.service
```

浏览器打开 `http://<机器IP>:8787`，输入刚才的口令。

打不开就依次检查：机器的防火墙 / 云厂商安全组有没有放行 8787；`systemctl status douyin-spark-fusion-web.service`；`journalctl -u douyin-spark-fusion-web.service -n 50`。

### 第 4 步：在面板里配好账号、好友、内容、时间

**全程在网页里点，不用手改配置文件。**

1. **扫码登录**：找到「扫码登录」这一块，点「开始扫码登录」。「抖音号」「备注名」可以留空（留空就用抖音自己的昵称和 ID）。用手机抖音扫码，再在手机上点确认。
   如果弹出「请输入验证码」，说明这个号被风控了，面板会切到二次验证界面——把手机收到的短信码填进去。
2. **选好友**：回到「账号与目标好友」，在这张账号卡上点「读取好友列表」，等它把会话读出来，勾上要续火花的人，保存。
3. **写内容**：账号卡里的「发送内容」，一行一句。默认模板长这样：

   ```
   [盖瑞]今日火花[加一]
   —— [右边] 每日一言 [左边] ——
   [API]
   ```

   方括号里的字只是普通文字，想怎么改都行；**只有 `[API]` 会被替换成一句每日一言**。不单独写内容，就用全局模板 `MESSAGE_TEMPLATE`。
4. **定时间**：账号卡里的「发送时间」填 `HH:MM`（比如 `20:30`）；不填就用全局的 `TASK_SCHEDULE_TIMES`（默认 `20:30`）。

每次保存面板都会先备份再原子写回 `.env`，你不需要碰它。

### 第 5 步：先空跑，再开定时

去「立即运行」，把档位选成 **「只选中不发送」** 或 **「输入后清空」**，点按钮，然后看「运行记录」：

| 档位 | 它做什么 |
| --- | --- |
| 只选中不发送 | 只验证能不能定位到每个好友，一个字都不发 |
| 输入后清空 | 真的把消息敲进输入框、读回校验，然后清空，唯独不点发送 |
| 真实发送 | 真发 |

两种空跑都正常了，再开定时器——**从这一步起才会每天真发**：

```bash
sudo systemctl enable --now douyin-spark-fusion-daily.timer
systemctl list-timers douyin-spark-fusion-daily.timer
```

想马上看到一条真发出去的效果，也可以先用「真实发送」手动跑一次。

## 之后每天会发生什么

1. 定时器每 5 分钟敲一次门，只有「到点」的账号才会动。
2. 到了设定时间，还会在**前后各 15 分钟**里挑一刻（同一个账号同一天固定，不会来回跳）。
3. 真开浏览器之前再随机等 0~90 秒，不天天卡在整分整秒。
4. 逐个好友发：间隔 8~20 秒，约 15% 的概率再多停一会儿；消息分段敲进去，像人在打字。
5. 发完写账本。没发成功的当天还会继续试；掉登录会提示你扫码，**扫完当天补发**。
6. 面板首页的「今天已发」是**真发出去**的数字。

## 面板里有什么

| 位置 | 你能做什么 |
| --- | --- |
| 首页 · 账号卡 | 看今天发没发、下次几点、卡在哪一步、连续多少天、内容预览、出口 IP；暂停 / 恢复、补发、移除 |
| 扫码登录 | 出码、手机确认、填短信验证码、取消 |
| 账号与目标好友 | 读好友列表、勾目标、改发送内容和时间 |
| 运行记录 | 每一轮的结论：发了几个、谁失败、为什么 |
| 运行日志 | 实时日志尾部，出问题先看这里 |
| 立即运行 | 手动跑一轮，可选空跑档位 |
| 运行配置 | 30 个常用键的表单（改完下一轮生效，端口类要重启面板） |
| 磁盘维护 | 浏览器缓存和孤儿资料目录的盘点、清理（可以只预演） |

## 新手最容易卡住的九个点

| 现象 | 原因 / 怎么办 |
| --- | --- |
| 面板打不开 | 先看服务活没活：`systemctl status douyin-spark-fusion-web.service`；再看防火墙 / 安全组有没有放行 8787 |
| 日志里说「没有配置访问口令，拒绝启动」 | 第 2 步没做，跑一次 `python -m webui.reset_password` |
| 忘了面板口令 | 同上，`python -m webui.reset_password` 直接改，不需要先登进去 |
| 二维码过期了 / 手机点了没反应 | 点「取消」重来；码过期会自动换新，换新后要扫**最新那张** |
| 面板跳出「请输入验证码」 | 这个号被风控了，填手机收到的短信码；填错可以重来 |
| 首页一直显示「今天没有账号到点」 | 正常：还没到你的发送时间，或者今天已经发完了 |
| 账号卡显示「登录已失效」 | 登录掉了（换网络、别处登录、太久没跑）：点「重新登录」扫码，成功后当天补发 |
| 显示「操作频繁 / 安全验证」 | 命中风控熔断，自动停 30 分钟；这期间不会跑，别反复点 |
| 一条都没发出去，却显示「今天已发」？ | 不会。只有回执核对通过才记 `ok`，失败一律记 `error` |

## 想改得更细

最常改的几个键（都在 `/opt/douyin-spark-fusion/.env`，也可以在面板「运行配置」里改）：

| 键 | 作用 |
| --- | --- |
| `TASK_SCHEDULE_TIMES` | 全局发送时间，默认 `20:30` |
| `SCHEDULE_JITTER_MINUTES` | 在设定时间前后各随机多少分钟，默认 15 |
| `MESSAGE_TEMPLATE` | 没单独写内容的账号用这套模板 |
| `DRY_RUN` | `off` 真发 / `select` 只选中 / `full` 输入后清空 |
| `PROXY_ADDRESS` | 全局出口，留空即直连；单个账号也能在账号卡里单独配 |
| `QUIET_WINDOW` | 禁跑时段，比如夜里不想让机器开浏览器 |
| `NOTIFY_WEBHOOK_URL` | 出问题时推一条通知（Server酱 / 企业微信 / 钉钉 / 飞书 / Telegram 自适应） |
| `TASKS` | 账号名单，面板会替你维护，一般不用手写 |

完整清单、默认值与逐条注释见 [`.env.example`](.env.example)。

### 命令行入口

| 命令 | 作用 |
| --- | --- |
| `main.py task` | 跑一轮（定时器走的就是这条） |
| `main.py dry-run [select\|full]` | 空跑一轮 |
| `main.py doctor` | 体检：账本还新吗、定时器和面板还活着吗、每个账号最近真发出去没有 |
| `main.py notify-test` | 试一下通知地址通不通 |
| `main.py prune` | 盘点磁盘（加 `--apply` 才真删） |
| `python -m webui` | 起面板；加 `--check` 只校验配置 |

退出码：`0` 整轮跑完（「没有账号到点」也算跑完）、`1` 被跳过或账号全部出错、`2` 参数错误。

### 升级、回滚、备份

```bash
sudo bash deploy/update.sh --check   # 有没有新版本
sudo bash deploy/update.sh           # 升级：只允许 fast-forward，不碰 .env 和 logs
```

回滚：`git -C /opt/douyin-spark-fusion reset --hard <提交号>`，再 `systemctl restart douyin-spark-fusion-web.service`。

该备份的（都等于凭据，别外传）：`.env`、`logs/login-profile/`、`logs/browser-state/`；历史记录在 `logs/runs.jsonl`。

## 已知边界

- 依赖抖音网页结构，改版可能让选择器失效——那时会记失败而不是假成功，日志里有定位线索。
- 一条内容发给全部好友，只有 `[API]` 那句不同。
- 同一个账号同一时间只允许一个浏览器（运行锁 + 面板互斥）。
- 仓库里的 `docker-compose.yml` 和 `docs/guide/` 有一部分来自上游（云函数 / GitHub Actions 形态），**本仓库实际支持的部署方式是自建机器上的 systemd**，新装请只按本页走。
